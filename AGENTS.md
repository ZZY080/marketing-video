# Marketing Video Agent Guide (PPT-Only)

This repository produces teaching/marketing videos from PPT slides and narration assets.

Pipeline:

`source -> outline/script -> slides.pptx (+ slides.pdf) -> ppt-screenshot -> tts -> srt -> render -> final MP4`

Default output: `1920x1080` MP4, per-slide narration, burned subtitles, and zero-padded slide frames (`slide-001.png ...`).

---

## Screenshot text integrity (mandatory)

**Why frames lose text:** `ppt-screenshot` is not a live PowerPoint window capture. When the input is `.pptx`, the tool typically converts via **LibreOffice** to PDF, then `pdftoppm` to PNG. LibreOffice often **substitutes fonts** and **reflows text**, which produces **truncated or missing words** compared to the deck you see in PowerPoint.

**How to prevent it (in order of reliability):**

1. **Always prefer a PDF exported by Microsoft PowerPoint** as the rasterization source. Save it next to the deck as `media/wip/<task-id>/slides.pdf`.
2. When `slides.pdf` exists, `ppt-screenshot` **automatically uses it** (no extra flags) so frames match PowerPoint layout.
3. On **macOS**, if `slides.pdf` is missing, the CLI may **auto-attempt** PowerPoint export via AppleScript; if that fails, **stop** and export PDF manually—do not assume `.pptx` alone is safe.
4. **`run-interactive` requires a PDF frame source** for step 1. If PDF cannot be obtained, the run must abort before TTS.
5. Use **`--strict-pdf`** on `ppt-screenshot` when you want **fail-fast** if no usable PDF is available (avoids silent LibreOffice fallback).
6. **`--pptx-path` and `--pdf-path` must not be passed together.**

**Hard rule:** Do not continue to `tts`, `srt`, or `render` until **every** `slide-*.png` has been checked for **no missing or truncated text** versus the source PPT/PDF. If any page fails, fix source or PDF export and **re-run** `ppt-screenshot` before downstream steps.

## 1) Repository Scope

- `scripts/` - CLI and pipeline implementation (TypeScript via `tsx`)
- `media/` - runtime workspace
  - `assets/` - shared brand assets
  - `inbound/` - input source files
  - `wip/<task-id>/` - task artifacts
  - `outbound/` - final videos

Per-task artifacts (`media/wip/<task-id>/`):

```text
source.md
outline.md
slides.pptx
slides.pdf                    # strongly recommended (PowerPoint export; preferred frame source)
slides/slide-NNN.png
segments.json
review/slide-narration-review.md   # produced by run-interactive before TTS
audio/segment-NNN.mp3
subtitles/all.srt
subtitles/segment-NNN.srt
clips/clip-NNN.mp4
concat.txt
PENDING_APPROVAL.md           # only when run-interactive runs without a TTY; see below
```

Final video: `media/outbound/<task-id>.mp4` (or custom `--out`).

## 3) Core Workflow

### Step 0 - Prepare source

Save source material to:

`media/wip/<task-id>/source.md`

### Step 1 - Prepare script

Create:

`media/wip/<task-id>/segments.json`

Rules:

- `segments.length` must match slide count.
- `index` must be 1-based sequential.
- `slideIndex` must point to existing slide.
- `narration` must be final spoken text.
- Leave `audioPath` and `durationSeconds` empty before `tts`.

### Step 2 - Create `slides.pptx`

Create:

`media/wip/<task-id>/slides.pptx`

Design guidance:

- Target 16:9, ideally 1920x1080 visual layout.
- Keep headline and body readable after export.
- Avoid overflow, clipping, and tiny text.
- Keep CTA and brand information visible on the final slide.

### Step 3 - Export PPT to frames

```bash
npm run video -- ppt-screenshot --task-id <task-id>
```

Default export policy (mandatory):

- Always prefer `slides.pdf` generated by Microsoft PowerPoint when available.
- If `media/wip/<task-id>/slides.pdf` exists, use it as the frame source (this avoids LibreOffice font substitution and text truncation).
- The CLI may auto-attempt PowerPoint PDF export on macOS when `slides.pdf` is missing.
- For `run-interactive`, PDF is required as the frame source; if auto-export fails, stop and do not continue.

Strict PDF (optional but recommended for CI or unattended jobs):

```bash
npm run video -- ppt-screenshot --task-id <task-id> --strict-pdf
```

Optional input override:

```bash
npm run video -- ppt-screenshot --task-id <task-id> --pptx-path /absolute/path/deck.pptx
npm run video -- ppt-screenshot --task-id <task-id> --pdf-path /absolute/path/deck.pdf
```

Output:

- `media/wip/<task-id>/slides/slide-001.png`, `slide-002.png`, ...

### Step 4 - Visual QA (mandatory)

Check every exported `slide-*.png`:

- no text overflow/clipping
- no missing/truncated title/body text compared with source PPT
- clear contrast and hierarchy
- accurate numbers and claims
- visible visual difference across adjacent slides
- final slide contains CTA/contact/brand copy

Chat-based review protocol (mandatory):

- In agent/chat delivery mode, slide review must be done in-chat, not only in terminal prompts.
- The assistant must generate/export and send slide images one-by-one in page order (`slide-001`, `slide-002`, ...).
- Do not ask for approval after each single image when user requested batch confirmation at end.
- After all slides are sent, ask one final question: whether all slides pass review.
- Only after explicit user approval of the full slide set may the workflow continue to `tts/srt/render`.
- If user rejects any slide, stop progression and fix/re-export before continuing.

If issues exist:

- First switch to PDF source exported by PowerPoint (`slides.pdf`) and rerun `ppt-screenshot`.
- If still broken, fix fonts/layout in PPT and rerun export.
- Never continue to `tts/srt/render` before frame text integrity passes.

### Step 5 - TTS

```bash
npm run video -- tts --task-id <task-id> [--voice <minimax_voice_id|auto>] [--tts-speed 1.0]
```

Default CLI voice is **`auto`**: per-segment language detection picks Chinese vs English MiniMax voices; pass an explicit `voice_id` to lock one voice for all segments.

This writes:

- `audio/segment-NNN.mp3`
- `audioPath` + `durationSeconds` back into `segments.json`

### Step 6 - Subtitles

```bash
npm run video -- srt --task-id <task-id>
```

Generates:

- `subtitles/all.srt`
- `subtitles/segment-NNN.srt`

Subtitle policy (mandatory):

- Default mode must be `semantic` (normal subtitle switching), not full-page static subtitle.
- `strict-single` is only allowed when explicitly requested by the user.
- Subtitles must stay page-bound: each `segment-NNN.srt` may only contain text from slide `NNN` narration.
- Sync priority: use TTS timestamps when available to keep voice and subtitle timing aligned.
- English subtitles must preserve readable spacing between words; remove garbled replacement glyphs (for example `�` or square boxes).
- For English (Latin) narration, on-screen punctuation is normalized to **Chinese full-width punctuation** (e.g. `，` `。` `！`); ASCII sentence punctuation must not appear in final SRT.
- Do not split **English words across cues** (e.g. `T` + `he`). The generator merges obvious TTS timestamp fragments and wraps lines on **word boundaries**; Latin lines are **rebalanced** so the last line is not a tiny orphan when it still fits the previous line.

### Step 7 - Render

```bash
npm run video -- render --task-id <task-id> [--out /absolute/path/output.mp4]
```

Render checks:

- slides exist and are sequentially numbered
- slide count matches `segments.length`
- all `slideIndex` references are valid
- each segment has `audioPath` + `durationSeconds`

## 3.1) Interactive full workflow (`run-interactive`)

Runs the pipeline with **human approval gates** between major steps. Order:

1. Export slide PNGs (**PDF source required**; see “Screenshot text integrity”).
2. Export `review/slide-narration-review.md` (per-slide narration for human read-through) — approve before TTS.
3. `tts` — approve before subtitles.
4. `srt` — approve before QA.
5. `qa` — approve before render.
6. `render` — final MP4.

**Terminal (TTY) mode:** after each step, the CLI prompts for `y` / `yes` to continue.

**Non-TTY mode (e.g. some automation hosts):** the run writes `media/wip/<task-id>/PENDING_APPROVAL.md` and exits with instructions. Continue the same stage by re-running with:

```bash
npm run video -- run-interactive --task-id <task-id> --approve-stage screenshot|narration|tts|subtitle|qa
```

**Rejection handling:** if the user answers `n` at a prompt, the CLI prints **suggested next steps** (paths to check, flags to change) and aborts; fix artifacts and re-run from the appropriate step.

## 4) CLI Reference

```bash
# initialize media layout
npm run video -- init

# generate one standalone image (optional helper)
npm run video -- image --task-id <id> --prompt "<prompt>" [--filename <name>.jpg]

# ppt -> slide frames
npm run video -- ppt-screenshot --task-id <id> [--pptx-path <absolute path>] [--pdf-path <absolute path>] [--strict-pdf]

# interactive full workflow with manual approval gates
npm run video -- run-interactive --task-id <id> [--pptx-path <absolute path>] [--pdf-path <absolute path>] [--voice <id|auto>] [--tts-speed <0.5-2.0>] [--subtitle-mode semantic|strict-single] [--approve-stage screenshot|narration|tts|subtitle|qa]

# import scene/shot script JSON to segments (optional)
npm run video -- script-import --task-id <id> --script-path /absolute/path/script.json

# narration synthesis
npm run video -- tts --task-id <id> [--voice <id|auto>] [--tts-speed <0.5-2.0>]

# subtitle generation
npm run video -- srt --task-id <id>

# final mp4 rendering
npm run video -- render --task-id <id> [--out <absolute path>]
```

Deprecated commands:

- `screenshot` (HTML flow removed)
- `validate` (HTML validation removed)

## 5) Quality Gate

A task is complete only when:

- [ ] `slides.pptx` exists and exports cleanly.
- [ ] If available, PowerPoint-exported `slides.pdf` is used as preferred frame source.
- [ ] `ppt-screenshot` generated `slide-001...slide-NNN`.
- [ ] Exported frame text is complete (no missing/truncated glyphs or words) vs source PPT.
- [ ] In chat-based runs, all slide images were sent in order and user explicitly approved the full set before next stage.
- [ ] `segments.json` exists and slide count matches frames.
- [ ] Visual QA passed for every frame.
- [ ] `tts` filled `audioPath` + `durationSeconds` for all segments.
- [ ] `subtitles/all.srt` exists.
- [ ] Subtitle style is normal switching (not static full-page subtitle), unless user explicitly requested static subtitle.
- [ ] Subtitle text is page-related (no cross-page carryover).
- [ ] Spot-check subtitle timing against audio on at least 2 slides (start/mid) before final delivery.
- [ ] `render` produced playable MP4 with burned subtitles.
- [ ] For interactive runs, each stage has explicit human approval before continuing.
- [ ] For interactive runs, per-slide narration review file is exported and approved before TTS.

## 6) Reusable Execution Prompt (Copy/Paste)

Use this prompt for future runs to avoid the same subtitle and screenshot issues:

```text
基于给定 PPT 和逐页脚本生成视频。要求：
0) 幻灯片导出必须使用 PowerPoint 另存的 slides.pdf 作为帧源，避免 LibreOffice 丢字；逐页截图在聊天里按顺序发送，全部发完后由我确认是否全部通过，未通过不得进入 TTS；
1) 字幕使用正常切换样式（semantic），不要整页常驻字幕；
2) 每页字幕内容只来自该页讲稿，不跨页；
3) 语音与字幕时间必须同步（优先使用 TTS 时间戳）；
4) 英文字幕单词之间必须有空格，清理乱码/方块字符；
5) 渲染前抽查至少 2 页，确认字幕切换与语音对齐后再交付。
```
